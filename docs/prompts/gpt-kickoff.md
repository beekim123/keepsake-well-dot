# 给 GPT 的提示词

把下面的提示词复制给 GPT（Codex 等编程智能体）。仓库根目录的 `AGENTS.md` 大多数编程智能体会自动读取，提示词里也要求它主动去读。

使用说明：
- 先把本目录（`keepsake-well/`）作为一个新仓库的根目录，在里面 `git init`。
- 把 Godot 4.7.2 编辑器放在仓库根目录（`Godot.app`，不提交），或者设置环境变量 `GODOT_BIN`。
- 第一次开工用"启动提示词"；中断后用"续跑提示词"；每个里程碑结束或质量下滑时用"自查提示词"；试玩后用"反馈提示词"。

---

## 1 启动提示词

```
你是这个仓库唯一的游戏开发者，一个人负责程序、美术、作曲、编剧和测试。

我们要做《拾遗井》（暂定名）：一款低难度的短途卡牌远征，2D 像素风，用 Godot 4.7.2 + GDScript 制作。玩家是小镇老井的新任守绳人，下井替镇上的人找回惦记的东西，借来用一趟，回来物归原主，换一段故事和一张永久新牌。故事用《炉石传说》冒险模式那样的方式在牌桌上讲，不做地图探索。

当前阶段的唯一目标：做出一个能从头玩到尾的核心玩法 demo（第 1 层），让我验证好不好玩。

开始之前：
1. 完整阅读 AGENTS.md 和 docs/README.md，再按 docs/README.md 的顺序读完 docs 里的全部文档。
2. 目录规则在 docs/tech/repository-layout.md：美术、声音、内容、Godot 源码、文档各自独立，必须遵守。
3. 美术和声音的制作方法参考 https://github.com/beekim123/rpg2d-dot （如果你能访问）：它的 resources/art、resources/audio、tools/resources 的代码思路可以参考改写，它的角色和美术素材不能用。

你的任务：
- 从 docs/plan/roadmap.md 的 D0 开始，按顺序做：D0 地基 → D1 规则可玩（灰盒）→ D2 叙事与表现 → D3 试玩版。
- 按 AGENTS.md 的工作循环持续工作：选任务 → 做 → 验证（跑测试和模拟，自己看截图和美术对照表）→ 记录 → 提交 → 下一个。
- 不要停下来问我。需要我决定的事写进 docs/plan/questions.md，按默认方案继续。
- 标【建议】【留白】的地方你可以自由发挥，改了就更新文档并说明理由。标【定】的不能改。「刻意不做」清单上的系统不要做。

硬性要求：
- 不调用任何图片/音乐/语音生成模型。所有图片用代码画出来导出 PNG；所有声音用仓库里的代码合成。
- 不使用外部美术和声音素材（OFL 字体除外），不复制任何现成作品的角色、名字、台词、旋律、界面图形。
- 规则代码与表现分离、确定性；有自动试玩模拟证明默认牌组能打通。
- 小步提交；提交前测试通过；每次提交后在 docs/plan/progress.md 最上面追加记录。

质量期望：好玩优先、清楚优先。D1 就要能完整玩通，用模拟数据证明难度合适；D2 让故事在牌桌上活起来。

现在开始：先读文档，然后在 docs/plan/progress.md 写一条"开工"记录（你对这个项目的理解、D0 的计划），提交，然后开始 D0 的第一个任务，并一直做下去。
```

## 2 续跑提示词

```
继续开发《拾遗井》。先读 AGENTS.md，再读 docs/plan/progress.md 最上面几条和 docs/plan/questions.md（看我有没有新的回答），然后从 docs/plan/backlog.md 接着做。按 AGENTS.md 的工作循环一直做下去，不要停下来问我。
```

---

## 3 自查提示词

```
先暂停新功能，用挑剔的玩家和美术总监的眼光做一次自查：
1. 运行 npm run check 和 npm run sim，对照 docs/plan/playtest.md 的目标区间。
2. 从标题玩到当前进度的结尾，用 npm run shots 截图，认真看每一张。
3. 列出问题清单：哪里不好玩、哪里看不懂、哪里不好看、哪里没声音、哪里有 bug、哪里文字溢出、哪里和设计文档不一致。按严重程度排序，写进 docs/plan/backlog.md 最前面。
4. 修掉所有严重问题，在 progress.md 记录自查结果，然后继续原来的工作。
```

## 4 反馈提示词

```
我试玩了最新版本，意见如下：
- （写你的意见，例如"首领太难""棉棉的台词太多""三选一看不清奇物效果"）

请把这些意见写进 docs/plan/backlog.md 的"用户反馈"一节，标为最高优先级，先改这些。每改完一条在 progress.md 说明改了什么（美术改动附对照表路径、数值改动附模拟结果）。改完后继续原来的工作。
```

---

## 5 美术返工提示词

```
我对（某个角色 / 牌桌 / 界面）的美术不满意：（具体哪里不好，想要什么感觉）。
请重新设计并重画，重新构建，对照 docs/art/art-direction.md 的自查清单检查。把新旧对照表放在一起给我看（路径写进 progress.md），然后继续原来的工作。
```
