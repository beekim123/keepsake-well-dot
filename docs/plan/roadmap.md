# 里程碑

按顺序做，不按日期。每个里程碑结束时，游戏都能从标题玩到当前进度的结尾。验收不通过就不进入下一个。

## D0 · 地基

目标：所有管线都通一遍，Godot 能启动。

- 按 [repository-layout.md](../tech/repository-layout.md) 建好全部目录、`.gitignore`、`package.json` 脚本。
- 美术：`palette.json`、`lib/png.mjs`、`lib/pixel.mjs`、`tools/resources/art.mjs`；画 1 个字符画素材（阿穗待机）和 1 个程序素材（面板九宫格）；build/verify/sheet 跑通。
- 声音：`synth.ts`、2 个音效（`sfx.ui_click`、`sfx.card_play_attack`）、1 段 8 秒测试旋律；导出 WAV、`audio:check` 跑通。
- 内容：`content/registry.json` + 一个最小 `cards.json`；`content:check` 跑通。
- 同步：`npm run sync` / `sync:verify`。
- Godot：工程设置（第 2 节）、AssetCatalog、AudioService、字体；标题画面显示文字和阿穗，点击发声。
- 测试：无界面测试框架 + 1 个规则测试。

**验收**：`npm run check` 全部通过；标题画面截图（3 倍放大）文字清楚、像素不糊。

## D1 · 规则可玩（灰盒）

目标：用简单的代码画灰盒图，完整玩通 demo 流程，并用模拟证明难度合适。

- 战斗规则全部实现：[02-rules.md](../design/02-rules.md) 第 4 节、全部牌、奇物、信物、敌人、首领。
- 路牌生成、事件、篝火、交换摊、✦ 与 ♥。
- 守绳屋、委托、归还（插画页先用纯文字页代替）、永久成长、存档。
- 战斗界面的可读性功能必须在 D1 做完：意图显示、"将受到 X"、出牌预览、规则牌。
- 自动试玩模拟与报告。

**验收**：
- 全部规则测试和边界情况测试通过；
- `npm run sim` 指标进入 [playtest.md](playtest.md) 的目标区间（或者在 progress 里写明偏差和计划）；
- 自己从标题玩到 demo 结尾一遍，记录一趟的实际时长。

## D2 · 叙事与表现

目标：故事"在牌桌上讲"，画面和声音达到 demo 质量。

- StoryPlayer 和全部插画页；BanterDirector 和全部台词触发；对手登场；牌桌彩蛋；信物登场、心愿、盖章演出。
- 全部正式像素美术（替换灰盒）：牌桌、人物、敌人、卡框、卡面、图标、界面、插画。
- 全部音乐、短乐句、音效、说话音。
- 设置菜单。

**验收**：
- `npm run shots` 的整套截图自己逐张看过，美术自查清单逐条通过；
- `audio:check` 通过，每首曲子在游戏里听过并写下听感；
- 从标题玩到结尾，没有占位图、没有静音的操作、没有文字溢出。

## D3 · 试玩版

目标：交给用户试玩，收集"好不好玩"的答案。

- 根据模拟和自己试玩调数值；修掉所有阻断性问题。
- 导出 macOS 版（Web 版可选）；写一页试玩说明（怎么打开、大概多久、想听哪些意见）。
- 把 [playtest.md](playtest.md) 的问卷整理好放在仓库里。
- 已知问题列表写进 backlog。

**验收**：导出包在一台干净的机器上能打开并玩到结尾；试玩说明和问卷就绪；打标签 `demo-1`。

## 之后（不在本阶段）

根据试玩反馈决定：继续做第 2 层「伞林」，还是调整核心循环。不提前开工。
